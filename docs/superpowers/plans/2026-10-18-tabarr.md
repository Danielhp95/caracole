# Tabarr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build tabarr, a nightly command-line tool that turns your Spotify Liked Songs and Learn playlist into a private library of sing-along chord sheets, lyrics and guitar parts, as `plan.md` v2.1 designs it.

**Architecture:** A Python package with a Typer CLI over one SQLite file. Ultimate Guitar is discovered through a local index built from its sitemaps, and matched offline. One polite HTTP client per provider caches every response and enforces the budget, the pauses and the back-off. Each nightly `tabarr run` syncs, refreshes the index, matches, fetches within budget, and writes `_todo.md`. Nix packages it, and a NixOS module runs it as a hardened oneshot on a timer.

**Tech Stack:** Python 3.14 (nixpkgs), httpx 0.28.1, selectolax 1.0.0, rapidfuzz 3.14.5, spotipy 2.26.0, typer 0.25.1, mutagen 1.48.1, tomlkit 0.15.0, pytest 9.1.1, `chordpro` 6.050.7, and torch, beat-this and librosa for auto-chords only.

**Spec:** `plan.md` (design v2.1), corrected by the spike findings in `docs/spike-2026-10-18.md`.

## Global Constraints

- Dependencies come from nixpkgs only: `buildPythonApplication`, with no uv, pip or PyPI pins.
- Never request `search.php`, `/tab/download`, `/tab/print?` or `/download/public/`. No proxies, no IP rotation, no browser fingerprinting.
- **Errors are not misses.** A 403, a 429, a challenge page or a parse failure is a provider error, never "not found".
- **On a block** (403, 429 or a challenge page): stop that provider for the rest of the run, cool it down for 24 hours, doubling on each repeat, and send one ntfy message.
- **UG budget:** about 60 requests per run (default 60), 10–20 seconds apart at random, one at a time. LRCLIB gets one lookup per song, ever. A miss may cost a second request, to the search fallback.
- Cache every raw response forever: 200 and 404 bodies. Sitemaps are revalidated with conditional GETs.
- **Matching:** accept at a score of 90 or more with a lead of 8 or more over the next different title; review at 75–90; otherwise not found. Fuzzy artist gate: 90.
- **Sheets:** complete means at least 80% of LRCLIB lines covered, where a line counts when rapidfuzz `partial_ratio` ≥ 85. Score coverage on the top 3 sheets by rating only.
- **Rating:** the Bayesian average `(v·R + m·C)/(v + m)`, with m = 10 and C = the vote-weighted mean of the song's versions.
- **Keep:** 1 sheet; 2 Guitar Pro (or Power Tab) parts; 1 tab.
- Skip UG `Official` versions and anything whose `tab_access_type` isn't `public`. UG type `Pro` is a public Guitar Pro file and is kept (spike).
- Guitar Pro mode is assisted: tabarr never downloads binaries from UG.
- Spotify redirect URI: `http://127.0.0.1:8888/callback`.
- The token lives in the state directory. Static secrets come in through `$CREDENTIALS_DIRECTORY`.
- The library layout follows plan §5. Files: `sheet.txt`, `sheet.json`, `sheet.cho`, `sheet.pdf`, `lyrics.txt`, `lyrics.lrc`, `guitar-N.<ext>`, `tab.txt`, `tab.json`, `info.json`, `sheet (auto).txt`.
- No Claude or AI attribution in commits, code or docs.

## Review Focus

1. **A challenge page served with HTTP 200** (Cloudflare's "Just a moment…"). The client must raise `ProviderBlocked`, not hand HTML to a parser that then reports "no versions". Test: Task 6 `test_challenge_page_with_200_is_a_block`.
2. **Song names with path-unsafe characters**, such as "AC/DC", "What's Up?", "Live: …", ".." or very long titles. Library paths must stay inside the library and stay stable between runs. Test: Task 14 `test_safe_name_*`.
3. **The budget running out in the middle of a song.** The song must stay dirty (neither found nor not found), and the next run must reuse the cached pages and finish. Test: Task 15 `test_budget_exhausted_mid_song_resumes`.
4. **Tab-page shape drift:** no `js-store`, no `versions` key, null `rating` or `votes`. A missing store is a `PageParseError` (a provider error); nulls count as 0. Test: Task 12 `test_missing_store_is_parse_error`, `test_null_rating_and_votes_are_zero`.
5. **The same song arriving twice:** liked and also in Learn, or a remaster id next to the original. It must become one song record with both source ids. Test: Task 4 `test_remaster_merges_with_original`, Task 10 `test_liked_and_playlist_dedupe`.

**A2. Spotify is optional, and the wanted list is a file.**
- `Config.spotify.enabled` is false without a `client_id`; the source is then skipped silently.
- A missing or expired token never fails a run. It becomes an ntfy alert plus a line on the to-do page.
- **The always-available source is `wanted.txt`** (`Config.wanted_file`, by default `library_dir/wanted.txt`, synced by Syncthing so it can be edited from a phone):
  - one song per line: `Artist - Title`, optionally followed by ` | Album` and/or ` | m:ss`;
  - `#` starts a comment, and blank lines are ignored;
  - the source is "wanted" and the source id is the line's identity key;
  - a song removed from the file stays in the database, the same as an unliked Spotify track.
- `tabarr add ARTIST TITLE [--album A] [--duration m:ss|seconds]` appends a line to `wanted.txt`, then syncs the file. The file stays the source of truth.
- `wanted.py` produces:
  - `WantedLine(artist, title, album, duration_ms, line_no)`
  - `parse_wanted(text) -> (lines, errors)`, where `errors` lists `(line_no, message)`
  - `append_wanted(path, artist, title, album=None, duration_ms=None) -> WantedLine`
  - `sync_wanted(conn, path, now, *, upsert=None) -> SyncStats`
- `spotify.sync_spotify(conn, sp, cfg, now, *, upsert=None)` works the same way. `upsert=None` means `tabarr.songs.upsert_song` (imported lazily); tests pass a recording fake.

**A6. Bare-id tabs (a finding from the full sitemaps).**
- **The problem.** About 10% of tab URLs are bare `/tab/{id}`. This includes every tab by an artist with a non-ASCII name (Joaquín Sabina, Maná, Héroes del Silencio, 宋冬野) and some accented titles, such as Soda Stereo's "De Música Ligera". The local index cannot see them.
- **The remedy has three parts.**
- **(1) Parse UG artist pages.** The `ug-parsers` agent writes `ug/artist.py`:
  - `UGArtistPage(artist_id, name, url, tabs: tuple[UGVersion, ...], page, pages, filters: Mapping[str, str])`. The `filters` map takes a kind to a URL.
  - `parse_artist_page(html, *, url=None) -> UGArtistPage`. It reads `data.other_tabs` and skips entries with no `type`.
  - `artist_page_url(base_url, *, kind=None, page=1) -> str`. Kind `guitar-pro` maps to `filter=guitar_pro`.
  - `UGTabPage` also gains `artist_url: str | None`, taken from `tab.artist_url`.
- **(2) The fetch phase (wave 2) uses artist pages** for accepted songs whose artist page is known, and for unmatched songs whose artist is known:
  - Learn an artist's URL from any fetched tab page and store it in `kv['ug:artist_url:<artist_key>']`.
  - For an unmatched song whose artist key exists in the index, fetch one slugged tab of that artist to learn the URL.
  - Fetch the `filter=chords` pages, cached 30 days. Match the title by fold, exact or fuzzy ≥ 90, against `song_name`, then treat the listed ids as the song's candidates.
  - Record the match as decision `accept` with step `artist_page`.
- **(3) Overrides.** `overrides.toml` gains `[artist_url] "Artist" = "https://www.ultimate-guitar.com/artist/<name>_<id>"`. The to-do page asks for it once per artist that has no slugged rows.
- **LaCuerda (Task 21) joins the MVP pipeline** for Spanish songs.

**A7. Browse and search.** You were asked mid-session ("Is part of the plan an interface for searching for songs and browsing what i already have?") and chose "Static page + CLI". It is not in plan.md, which deferred any web UI.
- **`Library/index.html`:** one self-contained page, regenerated wherever `_todo.md` is.
  - It shows every song with status, key or transposition, and links to `sheet.pdf`, `sheet.txt`, the lyrics and the guitar files, plus buy and search links for songs without a sheet.
  - A live filter ignores accents and also matches pinyin for Chinese titles, and you can filter by status.
  - No server and no external resources.
  - All song data sits in a `<script type="application/json">` block and is rendered with `textContent`, never `innerHTML`.
  - `library_page.py`: `build_library_page(conn, cfg, overrides, now) -> str` and `write_library_page(library_dir, html) -> Path`.
- **`tabarr search QUERY [--limit N]`:** offline, with no network requests.
  - It shows matches in your library (fuzzy over artist and title, accent-insensitive, with pinyin for Han text) and matches in the local UG index (fuzzy over artist and song keys, with counts per type).
  - Each UG hit is printed with the `tabarr add` line to paste.
  - `search.py`: `search_library(conn, query, limit=10) -> list[LibraryHit]`, `search_index(conn, query, limit=10) -> list[IndexHit]`, and `display_from_keys(artist_key, song_key) -> (artist, title)`.
