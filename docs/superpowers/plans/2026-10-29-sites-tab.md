# The Sites tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Sites tab on the library page (Library · Songbooks · Sites · Requests): one line a site, what caracole has
indexed from it, what your library keeps from it, last night's requests, its status, and, opened, robots.txt and the rest.

**Architecture:** a new module, `src/caracole/sites.py`, reads every figure from the database, the config and
caracole's own tables (never a request) and returns the tab's data; `library_page.build_library_page` puts it in the
page's JSON as `data["sites"]`, for the written file and the served page alike; a new `library_assets/sites.js` draws
the ledger from it, styled by `sites.css`.

**Tech Stack:** Python 3.14 (standard library, sqlite3), the page's plain JS and CSS (inlined by hash), pytest with
pytest-xdist, Chromium for browser tests (`helpers.browser`).

**Spec:** `docs/superpowers/specs/2026-10-29-sites-tab-design.md` (read it first; the mockup it names shows the look:
`/home/dani/Projects/caracole/.superpowers/brainstorm/4030753-1793241040/content/sites-ledger.html`, which is not in git).

## Global Constraints

- Branch `sites-tab` (requests-tab + main merged, 82f3a18). Never touch the main checkout at /home/dani/Projects/caracole.
- AGENTS.md binds every task: test first; `nix develop -c pytest -q -m "not slow"` while working and
  `nix develop -c pytest -q` before each commit; `nix develop -c ruff check --select E4,E7,E9,F src tests` clean;
  `git add` new files (the flake sees tracked files only); conventional commits scoped by area; no AI attribution
  anywhere.
- The tab sends no request and adds none to building the page.
- Page rules: elements built with `createElement` and `textContent`, never `innerHTML`; assets listed in
  `library_page.STYLESHEETS` / `SCRIPTS`; nothing loaded from the network; works in the file read from disk.
- Times shown as `stamps.shown(dt, …, local=True)` text computed in Python ("2026-10-29 03:14 EDT"), never relative.
- Status words: `OK`, `Indexing`, `Cooling down`, `Errors`, `Off`; each a badge with a dot and the word.
- Order of sites: `ug`, `lacuerda`, `lrclib`, `gtptabs`, `musescore`, `harptabs`, `gametabs`, `youtube`
  (icons.SOURCES' order without `auto` and `inbox`).
- Phone: four tabs on one line beside the mark at 390 px, no sideways scroll; light and dark.

## Review Focus

- A fresh library (no index built, no nightly run yet, no files): every line shows "—"/"No run yet", OK or Off, and
  the page still loads (Task 2's and Task 4's empty-database tests).
- A run still in progress when the file was written (`run:last` with `finished` null): the header gives the start
  alone (Task 4's `test_a_run_with_no_end_yet_gives_its_start_alone`).
- A site turned off in caracole.toml, or YouTube with auto-chords absent: Off, its Last night "—", its line dimmed, never
  "0 of 20" (Task 3 and Task 5).
- A provider in its cooldown: "Cooling down" with its until-time and the block's message, and its index never shown as
  complete because of it (Task 3).
- A song whose sheet came from LaCuerda while UG's index lacks it: counted under LaCuerda only; a song counted once
  per site however many files it has there (Task 4's `test_a_song_counts_once_per_site`).

### Task 4: What your library keeps, last night, and the tab's data in the page

**Files:**
- Modify: `src/caracole/sites.py`, `src/caracole/library_page.py` (`build_library_page`, after `data["songbooks"]`)
- Test: `tests/test_sites.py`, `tests/test_library_page.py`

**Interfaces:**
- Consumes: Tasks 1–3; the song cards `build_library_page` already made (`song_cards`: each card's `files` with
  `name` and `source`, its `source`, `museScore`, `versions`); kv `run:last` (`started`, `finished`, `requests`,
  `budgets`: pipeline.py `_report_json`); `cfg.provider(p).delay` and `.budget`; the last `events` row per provider.
- Produces: `def sites_data(conn, cfg: Config, cards: list[dict[str, Any]], now: datetime) -> dict[str, Any]`, the
  page's `data["sites"]`, exactly:

```
{"run": {"started": str, "finished": str | None, "requests": int} | None,   # shown() text; None: no nightly run yet
 "totals": {"sites": 8, "indexed": int, "kept": int},
 "songs": int,                                                             # len(cards)
 "list": [{"key": str, "name": str, "role": str, "domain": str,
           "indexed": {"songs": int, "unit": str, "detail": str} | None, "asked": str | None,
           "progress": {"done": int, "of": int, "what": str} | None,
           "kept": {"count": int, "unit": str, "songs": int, "detail": str | None},
           "night": {"used": int, "budget": int, "unit": str} | None,      # None: no run, or the site is off
           "status": {"state": str, "label": str, "detail": str | None},
           "pace": str, "last": str | None,                               # last request's time, shown() text
           "robots": {"text": str, "paths": [[str, str], ...], "more": int},
           "terms": str | None}, ...]}
```

  Kept units and counts, per site: ug and lacuerda "sheets" (cards whose `source` is the site; ug's `detail` "+ N other
  versions kept beside them", N the sum of `len(versions.list) - 1`); lrclib "lyrics" (cards with a `lyrics.txt` or
  `lyrics.lrc` of source lrclib; `detail` "N of them synced", the `.lrc` ones); gtptabs "Guitar Pro files" (files named
  `guitar-N.*` of that source); musescore "links" (cards with a non-empty `museScore`); harptabs "harmonica tabs"
  (`harmonica-N.txt`); gametabs "tabs" (`gametab-N.txt`); youtube "auto sheets" (cards whose `source` is youtube).
  `kept.songs` counts cards, for the share. A site's index is partial (`status_of(..., partial=True)`) while its `progress` has
  `done < of`. Night unit "yt-dlp runs" for youtube, else "requests". Pace from `delay`:
  "10–20 s between requests", "1 s between requests" when both ends match, "15–30 s between runs" for youtube.
