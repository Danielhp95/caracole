# tests/conformance: what the phone must agree with

The conformance corpus: what caracole's Python code answers, written as data by the Python suite and read by the
Kotlin port's tests (android/), so the phone agrees with the computer to the byte. The spec is
docs/superpowers/specs/2026-11-03-conformance-corpus.md.

- `data/caracole/<area>/`: runtime data the phone ships (a resource root of `:core`): Unicode tables, keys, pinyin,
  the schema (`schema/migrations.json`, and `schema/phone.sql`, hand-written), the page's asset order.
- `vectors/<area>/`: test vectors, `<name>.jsonl` (a header, then a record a line) or `<name>.json`, and fixtures,
  `vectors/<area>/fixtures/<name>.jsonl` (a database's rows, kv and files, replayed on both sides). Gradle hands the
  folder to every Kotlin test as the system property `caracole.conformance`.

Every file but `data/caracole/README.md` and `data/caracole/schema/phone.sql` is generated by a
`tests/test_conformance_<area>.py` through `helpers.corpus.check`, which fails when the committed file differs.
Never edit one by hand; regenerate:

    CARACOLE_CORPUS=write nix develop -c pytest -q -n 0 tests/test_conformance_*.py

then run the Kotlin side against it, `nix develop ./android -c gradle -p android test`, before merging (the drift
protocol, in the spec).
